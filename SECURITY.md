# 安全与问题反馈 / Security

请不要在 issue、日志或问题报告中粘贴真实 Personal Context、私密 Store、访问令牌、简历、对话记录或其他敏感内容。

如仓库已启用 GitHub Private Vulnerability Reporting，请优先使用该入口；否则请先通过维护者公开资料中的私密联系方式联系维护者。不要创建含敏感数据或可直接利用细节的公开 issue。

报告建议包含：受影响版本、最小复现步骤、预期与实际行为、影响范围，以及不含真实个人资料的合成样例。请删除本机绝对路径、身份信息、令牌和完整上下文。

Brief Yourself `1.0` 不承诺安全响应时限、生产环境可用性或绝对安全。测试结果只说明对应输入与环境下的检查范围。

---

Do not include real Personal Context, private Stores, access tokens, resumes, conversation history, or other sensitive material in issues, logs, or reports.

Use GitHub Private Vulnerability Reporting when it is enabled. Otherwise contact the maintainer privately through the contact information on their public profile. Do not open a public issue containing sensitive data or directly exploitable details.

A useful report includes the affected version, minimal reproduction steps, expected and actual behavior, impact, and a synthetic example. Remove local absolute paths, identity data, tokens, and complete Context.
